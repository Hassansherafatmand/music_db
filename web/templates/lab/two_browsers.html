Try it (2 minutes)

  1. Open this page in Chrome and log in as sunny_cactus40 (password music330).
  2. Open the same address in Safari (or a private window) and log in as brave_falcon3. The two session names are different.
  3. In Chrome, press ♥ on the song above. Refresh Safari: the ♥ number and “favorites” went up by one.
  4. In Safari, open My favorites: it shows brave_falcon3's songs, not sunny_cactus40's. Same server, same tables, but each SQL uses WHERE listener_id = <who is logged in>.

And if both browsers change the same playlist at the same time? Adding a song is a transaction that first locks the playlist's row: SELECT … FOR UPDATE. The second browser waits a few milliseconds until the first one is finished, so both can't take the same position.
