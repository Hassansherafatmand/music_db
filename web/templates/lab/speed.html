Indexes and EXPLAIN

An index is like the index at the back of a book: MySQL jumps to the right rows instead of reading the whole table. EXPLAIN shows MySQL's plan. Look at type (ALL = read every row, range/ref = use an index) and rows to read.

ALL reads the whole table index reads the whole index range reads only a part of an index fulltext uses a FULLTEXT index With only about 1,200 songs and 9,000 plays, every query is fast. With millions of rows, the difference is huge.

The index idx_song_name is sorted by the first letters, like a phone book.

2. The plays of one day

The index idx_play_played_at keeps played_at in order.

{{ race(plays, [("A range on the column", "good"), ("A function around the column", "bad"), ("The range, without the index", "bad")]) }}

The lesson: WHERE DATE(played_at) = … looks simpler, but MySQL must run DATE() on every row first, so the index can't help. Write the condition on the column itself: played_at >= day AND played_at < day + 1.
